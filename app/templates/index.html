使用说明

一、系统组成

本工具基于 PaddleOCR 3.5（百度飞桨）识别引擎 + PyMuPDF（PDF 解析）构建。整体分为三部分：

模块功能
上传 & 预检接收 PDF/图片上传，检测文件类型、页数、是否可处理
识别管线PDF 分析 → 页面分类 → 文字提取/OCR → 表格检测 → 图片识别 → 印章检测 → 排版输出
结果导出生成 Word（.docx）正文 + 嵌入表格、Excel（.xlsx）多 Sheet 表格、ZIP 归档下载

二、识别逻辑

1. 电子 PDF（有文字层）

直接从 PDF 文本层提取 文字 + 字体 + 字号 + 颜色，保留原始格式。
表格：用 PyMuPDF 内置的线条/文字间隙检测自动发现。
速度：每秒 20-50 页，无 GPU 需求。

2. 扫描件/图片（无文字层）

先渲染为 250 DPI 图像 → PaddleOCR 逐行识别文字 → 图像线检测 找表格边框 → 逐网格 OCR 填单元格。
表格：通过横向/纵向投影找到网格线位置，重建行列结构。
速度：纯 CPU 首次约 5-10 分钟（ONEDNN 编译），后续每页 10-30 秒。

3. 印章识别

基于 HSV 颜色空间（红/蓝印章）+ 椭圆拟合 + 纹理密度检测。仅对彩色扫描件有效，灰度件自动跳过。
检出的印章独立裁剪为 PNG 嵌入 Word 文档。

三、参数说明

参数默认值说明与例子
DPI250 扫描件渲染精度。数值越高图像越清晰、表格线检测越准，但处理更慢。
例：150=快速预览 / 250=标准文档（推荐） / 400=精细表格公式
OCR 语言ch 仅对扫描件生效。ch=中文简体 / en=英文。
例：中英文混合合同选 ch；全英文合同选 en 可提速
表格检测开启 是否提取表格。关闭后仅输出纯文字段落，不生成 Excel 表格 Sheet。
例：纯公文无表格可关闭以提速
表格检测策略auto 仅对电子 PDF 生效。控制如何发现表格：
lines = 靠 PDF 中的矢量框线找（适合招标文件、有边框表格）
text = 靠文字之间的空白网格找（适合无线条的对齐文字表格）
auto = 两者结合（默认）
例：政府招标文件选 lines；Word 另存的无框表格选 text
相邻表格合并关闭 仅对电子 PDF 生效。开启后，连续两页上列数相同的表格会拼接成一张。
例：大表格跨多页时选开启；独立小表格在独立页面选关闭（推荐）
印章检测开启 是否检测公章/印章。扫描件为灰色时可能无效果。
例：彩色扫描合同选开启；黑白复印件可关闭
识别图片0 控制图片/图表区域的检测强度。仅对扫描件/图片生效。
0=仅识别文字，忽略图片区域（推荐，速度最快）
1=适量图片识别，适合图文混合文档
2=深度图片识别，适合图片密集型文档
⚠ 过高可能导致文字被误识别为图片，丢失正文内容
例：纯合同文本选 0；产品手册含截图选 1；海报宣传册选 2
单独导出图片关闭 是否将 PDF/扫描件中的图片区域单独裁剪导出为 PNG 文件。
开启后会在 ZIP 包的 images/photos/ 目录下生成逐页裁剪的图片。
⚠ 会逐页分析像素纹理密度，每页增加约 2-5 秒处理时间
例：纯公文无图片选关闭；合同含公章/扫描件选开启以存档

四、注意事项

  • 文件大小：建议单个 PDF 不超过 200 MB。超大文件处理时间较长。
  • 扫描件首次慢：第一次处理扫描件时，系统需编译 ONEDNN 推理内核（约 5-10 分钟），后续会快很多。
  • 表格精度：电子 PDF 的表格依赖原文件中的线条或文字排版。Word 另存为 PDF 时建议勾选"保留可编辑文字"，避免文字被矢量化。
  • 印章遮盖：盖在公章下的文字无法被 OCR 识别（物理遮挡），这是所有 OCR 的固有局限。
  • 手写体：签名、手写日期等识别精度低于印刷体，属正常现象。
  • 输出格式：生成 .docx + .xlsx + .zip（文件名为 原文件名_时间戳.zip），不支持输出原 PDF 格式。
  • 加密 PDF：暂不支持有密码保护的 PDF 文件。
  • 多文件对比：当前版本每次仅处理一个 PDF。如需批量对比表格数据，可下载 Excel 后人工对比。
